# Contributing to FastMart 🚀

Thanks for considering contributing! Follow these steps to ensure a smooth process.

## 📝 How to Contribute

---
1. **Find an issue**  
   - Check [GitHub Issues](https://github.com/harisalimughal/FastMart/issues) for tasks labeled `good first issue` or `Todo`.  
   - If no issue exists for what you want to work on, [create one first](#-creating-an-issue).
---

2. **Issue assignment**  
   - A collaborator will assign you the issue.

---
3. **Fork & Clone the Repository**

    - Fork the repository
    - Clone using: 

    ```sh
    git clone <repo-url>
    ```

---
4. **Set up your environment**

   - Navigate to the project folder:

   ```bash
   cd FastMart
   ```

   - Install dependencies:

   ```bash
   npm install
   ```

---
5. **Create a Branch**

   - Create a new branch from `main`:

   ```bash
   git checkout -b <branch-name>
   ```

   - Use a branch name that reflects the issue you're working on, like `fix/login-bug` or `feature/add-navbar`.

---
6. **Make Your Changes**

   - Write clean and well-documented code.

   - Follow the project’s coding style.

---
7. **Open a PR**

   - Go to your forked repository on GitHub.

   - Click on the "New Pull Request" button.

   - Follow the template below when opening a PR:

   ---

   ### PR Title

   `[Issue #<issue-number>] Short description of the change`

   ### Description

   - Briefly explain what the PR does.

   - Mention any relevant issues.

   ### Screenshots (if applicable)

   - Attach screenshots for visual changes.

   ### Testing Instructions

   - Steps to test the feature.

   - Edge cases tested.

---

8. **Wait for Review**

   - A contributor will review your PR.

   - Make any requested changes.

   - Once approved, your PR will be merged!

---

## ✨ Creating an Issue

Before working on a feature or fix, you must create an issue and wait for a repository contributor to review and accept it.

### Issue format

Each issue should follow this format:

---

#### Task  
A brief description of the task or feature request.  

#### Acceptance Criteria  
- List the expected behaviors or changes.  
- Define success conditions for the implementation.  

#### Testing Requirements  
- How will the feature be tested?  
- What edge cases should be considered?  

#### Dependencies  
- List any related issues or external dependencies (if any).  

### Issue Acceptance

- Once you submit an issue, a contributor will review it.
- If accepted, the contributor will approve it and add the Todo label.
- Only then can you self-assign and start working on it.
